# Lovart 页面、评论与 Agent 联动：Nomi 应怎样减少操作

📋 方案补充，未实施。日期：2026-10-12。用户指向已打开的 [Lovart](https://www.lovart.ai/) 画布，并明确：Nomi 左侧目录的核心作用是分开不同页面，希望改用页面式导航，同时让评论/涂鸦与左侧 Agent 顺畅联动。

## 1. 本轮实际看到了什么

在用户已打开的登录态项目里，通过 Chrome UI 查看并做可逆的页面/工具切换。没有新增页面、提交评论、画新笔迹或发送 Agent 请求；结束时回到原页面及移动工具，原输入草稿保留。本文不公开用户项目 id、截图或草稿原文。

| 观察 | 实际操作与结果 | 可以借鉴什么 |
|---|---|---|
| 顶部页面标签 | 看见页面 1、页面 2 与新增标签入口；点击页面 2 后切为空画布、缩放为 100%，回到页面 1 后原内容与 133% 缩放恢复 | 把画布分区直接呈现成页面，点击就换工作面；不必先展开目录再找分类 |
| 左侧 Agent 持续在场 | 页面切换期间左侧输入草稿与已有引用保留 | 一个项目里连续创作，换工作面不等于换对话或丢草稿 |
| 底部工具集中 | 选择/移动、评论、涂鸦、图像生成处于画布底部；评论模式上方展开少量局部工具 | 主动作在当前工作面就能到达，工具按当前模式展开 |
| 评论与输入引用对应 | 画布已有编号标记，左侧输入框已有对应编号/媒体提示的引用；点击已有标记可打开文字、类型、删除/更新控件 | 评论可以成为 Agent 的可见上下文；从引用回到画布目标的设计值得学 |
| 涂鸦按需展开 | 打开涂鸦后能看到画笔宽度，以及铅笔、文字、矩形、线、箭头等选项 | 初始界面保持轻，表达位置/形状时才显露工具 |

证据限制：这只是当前项目中的 UI 观察。已有评论引用在查看前就存在，本轮未新建评论，**不能据此证明“每次点击素材都会自动追加输入引用”或评论的服务端持久化/提交协议**。当前画布素材内容包含视频界面，但一次 DOM 检查没有找到 video 元素；不能凭素材中的播放器画面推导 Lovart 已把评论绑定到真实视频 PTS。本轮不研究它的私有实现，也不把它列为开源底座。

## 2. 对 Nomi 的判断：目录实际承担的是页面导航

用户这次强调的是交互组织，不是把画布压成一个长页面。建议把“切到哪张工作画布”直接做成顶部页面标签；页面里继续有节点、组、素材和关系。画布分区、组内组织、实际文件存储各做自己的事，不让创作者先理解文件目录层级才能开始。

Nomi 当前分类没有 parent 目录层级，项目内共用一张 graph，以 categoryId 过滤可见节点；组再归属于分类。按分类保存视口的运行期能力已经存在，但项目 payload 没有持久化 categoryViewports，切项目会清空，不能称作已有重启恢复。详细 owner 与固定 SHA 证据见[页面接缝审计](lovart-pages-nomi-audit.md)。

**推荐第一步复用 category 身份做页面式导航，不立刻迁移数据模型。** 用已有 id 选择当前工作画布，保持现有节点、组、生成目标和素材引用。用户看到更直接的页面切换；内部仍沿原 owner。内置 shots/cast 等分类绑定分镜渲染、编号和默认落点，因此不能把所有分类随意改名为“页面 1/2”并假设领域行为自动成立。

“任意页面均可任意混排成果”可以是后续目标，但需要先把页面身份与节点领域类型/默认路由解耦，再设计兼容与迁移；这不是只换一排标签。本轮交方案，不删除现有目录、不改分类、不迁移旧项目。

当前 Agent 读画布投影没有独立的页面列表/归属字段，创建也可能按角色/镜头等类型默认分发。因此页面与 Agent 的首轮接线必须补可读页身份和明确目标范围；若入口承诺“在本页创建”，就要在共享创建边界冻结并验证实际落页。不能只把标签高亮，就宣称 Agent 已理解当前页。完整自由页面的编号/渲染/迁移仍单独收口。

## 3. 重点是让画布成为输入面

建议分清两个状态：**当前点选的对象上下文**与**此次已加入草稿的反馈集合**。这是内部职责，界面不要求用户学习术语。

| 用户动作 | 画布与 Agent 的建议联动 | 保留的控制 |
|---|---|---|
| 点一张图片或视频 | 左侧 Agent 的当前对象区直接显示缩略图、对象名、结果版本；视频显示当前时间。面板折叠时显露紧凑上下文，可继续输入要求 | 普通选择不发模型请求；不重写已有输入，也不把每次选择永久堆成附件 |
| 进入评论后点位置 | 就地输入意见；左侧同步出现同编号的反馈草稿卡片，自动带素材版本、点/区域、视频采样时刻 | 不再要求点击“添加附件/添加到对话”；输入仍在正在写的评论处，不抢键盘焦点 |
| 使用涂鸦表达问题 | 画布标记与左侧预览同步；结束标注后回到同一输入框补要求 | 标注层与原素材分开；真内容绘画继续走已有白板语义 |
| 从 A 点到 B | 当前对象区更新为 B；已写给 A 的反馈卡片保持 A 的冻结身份 | 不把 A 的意见悄悄改成 B；没写内容的临时上下文不污染批次 |
| 换页面 | 切换可见 graph 分区并恢复该页运行期视口；Agent 保持同一项目会话，显示当前页面名；草稿中的跨页引用保留来源标签 | 草稿不随换页清空；不将页面当授权边界或默认允许修改整页 |
| 点左侧反馈卡片 | 回到它的来源页面、具体节点/结果/时刻并高亮；原版本不可用时说明变化并提供回看/重选 | 自动跳回只负责查看，不重发生成，不用新结果替换旧意见的目标 |
| 点击发送 | 一次提交明确可见的反馈集合、额外文字和必要媒体上下文 | 继续用主方案的版本/能力/费用门；准备失败保留草稿，ACK 只清理本批次 |

核心减少的是四步：打开 Agent、重新找素材、上传同一素材、用文字重复定位。自动显露上下文不等于自动执行。已经输入的意见与素材版本必须可检查；“点了就显示”不应变成“点一下就生成”。

## 4. 自动展开应顺着人的动作

进入评论/标注属于明确表达修改意图，可以自动展开左侧 Agent 并带入反馈卡片。普通选择只更新紧凑上下文，必要时显露输入入口；拖动画布、移动组、播放/暂停、拖播放头不反复展开面板或抢焦点。图像/视频内容选择与画布拖动要沿既有事件边界区分。

用户正在 inline 评论里打字时，镜像卡片不能把输入焦点拉走。用户结束这一条意见后，可把焦点交回已有 Composer，保持之前文字、附件、技能和未发送内容。无需新增第二个浮动聊天窗。

视频只是在播放时改变的画面。进入定点评论时先暂停并捕获实际帧；此后播放头移动，已写意见仍对应当时的帧/源时间。只看某一帧的评论不代表已追踪整个视频对象。取帧和模型输入边界沿[媒体反馈方案](media-feedback.md)，不要因 UI 顺畅就省掉身份和时间信息。

## 5. 页面标签需要补齐的行为

- **页面很多时：** 标签横向滚动，并有可搜索的全部页面入口；无需常驻大目录。只切活动页，不能同时创建多份 React Flow/视频运行时。
- **切换后返回：** 先复用现有按分类记忆视口；若要求关窗/换项目后仍恢复，明确补持久化与旧数据兼容，不能把运行期记忆写成已完成。
- **关闭与删除：** Lovart 当前有“关闭标签页”可见入口，但本轮未操作，删除语义未知。Nomi 建议关闭仅隐藏打开的标签，不删内容；从全部页面可再打开。真正删除页面另走明确的现有删除/撤回语义，不能因照抄 x 按钮而丢节点。
- **跨页引用：** 当前边存全图，画布只画两端在当前页的边。用来源页/对象引用提示依赖，Agent 回执可跳回；不能把跨页引用偷偷截断，也不能将同一个源媒体复制出多份 owner。
- **Agent 归属：** 首轮仍沿既有项目会话和执行目标，不按每张页面新建一套 Agent。草稿显示来源页，执行批次仍冻结具体目标，避免切页改变已提交工作。

## 6. 与已有方案怎样合并

这不是第三套产品架构：页面标签负责工作面切换，评论/涂鸦负责表达位置，左侧 Composer 承接意图，既有 Agent/生成入口负责执行，反馈记录负责对齐与验收。Codex 提供“标注如何变成输入”的静态机制参考；Lovart 提供“页面、工具与 Agent 如何同时在场”的当前 UI 参考；OpenDesign 等开源项目提供可研究的锚点/评论/轻编辑模块。

先用生产组件给“顶部页面 + 单画布 + 左侧 Agent + 底部模式工具”的候选，不凭研究文档直接改界面。候选需覆盖旧目录功能去向、窄窗口、键盘切页、跨页草稿、关页/恢复和失败状态；一经用户确认，再生成 board 清单。这里建议改变导航形态，不要求照搬 Lovart 的颜色、图标或整个布局。

验收沿媒体试点追加：统计从看到问题到输入准备完成的点击数、人操作时长、位置复述次数和误带目标次数；对比当前目录/手动附件流程。普通选择、评论模式进入、切页、从反馈返回素材分别登记性能场景。选中时可见反馈要满足仓库预算；面板自动展开后的布局跳动、输入焦点丢失、切页引起重复生成均为阻断项。所有收益与性能当前未测量。

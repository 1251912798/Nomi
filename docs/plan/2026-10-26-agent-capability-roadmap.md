## 为什么要这份路线图

定位是「从写剧本、做视频、弄素材、做剪辑到成片，全程用这个 Agent」。对照代码，Agent 的骨架（单一工具注册表、花钱边界、看门狗、压缩、插话、存技能）是扎实的；短板集中在**做完以后知不知道做得对**：

| 缺口 | 证据（2026-10-26 核） |
|---|---|
| 没有常驻尺子 | `evals/baselines/journeys.json` 停在 2026-06-14、2 条旅程、`tokensTotal: 0`；pi lane 切换（#646，09-09）后没有真实模型基线。真实模型数字都是一次性证据（`docs/evidence/2026-09-2x-askback-real-model-run1..9`）。身份提示词 `electron/harness/context/agentContext.ts` 里堆着 08-28 / 09-10 / 09-15 / 09-21 / 09-22 的补丁注释，改完有没有伤到别处量不出来 |
| 记忆半套 | 有项目记忆卡 `electron/memory/projectMemory.ts`（事件日志规则提炼，零 LLM，注入 ≤1500 字），但：只认画布角色/场景卡、锁定、改写提议；剧本、风格、否掉的方案进不去；Agent 没有写记忆的动词；「AI 记得 N 条」`MemoryFold.tsx` 外壳迁移后没挂回（孤儿）；`agent.proposal.approved` 的发送方 `agentChatTrace.ts` 零生产调用者；经验闭环 `electron/experience/*` 三个文件零生产调用者；跨项目一条都没有 |
| 交出去不管 | 生成任务归 ProductionRun 管（对的），但 Run 完成只触发 `laneDesktopTasks.ts` 的界面刷新，**不叫醒 Agent**；面板 `running` 只看「回合活着」（`useAgentPanelV4Data.ts:106`），后台生成时小球显示空闲 |
| 看不见 | 读素材动词 `look_at_media` 说明里写明「never describes what is visible or audible」。另有一条现成的看图通道 `shotVerifyJudge.ts`（抽帧 → 多模态判分，批量生成后与 Run 的 qa 阶段在用），但不是 Agent 能调用的动词，且非多模态模型时静默跳过 |
| 模型无底线 | 大脑 = 用户接的任意文本模型（`textBrainResolver.ts` 的 `chooseTextModel`），唯一门槛是能调工具；**产品默认大脑 `deepseek-v4-pro` 是纯文本**（`electron/catalog/apimartTexts.ts:52`）。目录里已有 `supportsImageInput` / `supportsToolCalls` 两个元数据可用 |

## 顺序

```
阶段 0  尺子 ───────────────┐
                            ├─▶ 阶段 1a 记忆
                            ├─▶ 阶段 1b 收尾 A（不靠眼睛）
                            └─▶ 阶段 2  眼睛 + 模型底线 ─▶ 阶段 3 收尾 B（看过再交）
                                                          └─▶（以后）主动性
```

| 阶段 | 做什么 | 完成的样子 | 依赖 | 粗估 |
|---|---|---|---|---|
| **0 尺子** | 复用 `pnpm eval:journey`（已有真实模型跑法、pass@k、`--model`）。按定位补 5 条旅程：①写剧本→拆镜 ②拆镜→建锚→出图出视频 ③镜头→时间轴→导出 ④说一条偏好、关掉重开、看它记没记住 ⑤故意放一镜坏的、看它发现没。指标按 R13.3：工具写对率、回合成功率，加每条旅程 pass@3。跑 2～3 个大脑（默认大脑 + 一个强模型 + 一个能看图的） | 一份当前 main 上的真实基线进 `evals/baselines/`；动 Agent 提示词 / 动词的 PR 跑小档（3 条），每周跑全档；④⑤ 现在应当红（那就是后面要补的） | 无 | 1 周 |
| **1a 记忆** | 一个家：现有项目记忆卡升级为「片子档案 + 进度」（人物、场景、风格、世界观、否掉的方案、交付规格、哪几场哪几镜做到哪）；新增「关于你」（范围见拍板 D2）；Agent 读写记忆的动词（形状对齐 Anthropic memory tool 的 view / create / str_replace / delete，文件约定对齐 pi 的 AGENTS.md，不自创协议）；规则提炼器保留为来源之一；界面一个家，聊天里只说「记下了」并指过去 | 旅程④由红变绿；记忆可看、可改、可删、可溯源；同提交删 `MemoryFold.tsx` 孤儿（或被新家复用）与 `electron/experience/*` 孤儿 | 0 | 2～3 周（含界面拍板） |
| **1b 收尾 A** | Run 状态进小球与面板（后台生成时是「长任务」不是空闲）；Agent 发起的 Run 跑完，排一条后续消息叫醒它，报「出了几条、失败几条、卡在哪」并给去处；小球「有新消息」接住 | 小样里「长任务」「有新消息」两个变体在产品里成立；不靠眼睛也不再「交出去不管」 | 0 | 1 周 |
| **2 眼睛** | 把 `shotVerifyJudge` 的抽帧 + 判分通道收成一个 Agent 读动词（看关键帧 / 缩略图，返回人话描述 + 是否符合锚），批量审片与 Run 的 qa 阶段改调同一个家（不留两份）；模型底线按拍板 D3 落地 | 旅程⑤由红变绿；默认大脑下也能看（见 D3） | 0 | 2 周 |
| **3 收尾 B** | 叫醒后先看一遍再报（一致性、跑脸、漏镜），交付前自检；花钱规则按 D4 | 旅程②③的「交出去的东西对不对」由人检查变成 Agent 先检查 | 1b、2 | 1～2 周 |
| 以后 | 主动性（闲时查资料、审画布，参考 Lovart Arti 的 Design Research / Design Review） | — | 1a、3 | 不排 |

1a 与 1b 改的文件不重叠，可以两条线并行；2 只依赖 0，可在 1a/1b 期间开始设计卡。

## 拍板时的四个选项（存档）

### D1 顺序

**默认：按上图。** 尺子先行，是因为后面每一步都要拿数字证明「变好了」，否则又会变成提示词里的一条补丁。

### D2「关于你」跨项目记什么

2026-06 harness 总方案 §C 写过「**不抄全局记忆**——创作项目间风格互窜是事故」（`docs/plan/2026-06-11-nomi-harness-master-plan.md:169`）。这条顾虑是对的，所以不是「要不要跨项目」，而是「什么能跨」。

| 选项 | 跨项目记什么 | 代价 |
|---|---|---|
| A 不跨 | 什么都不记 | 每个新项目从零教一遍「先问还是直接做、回复多长、常用片型」 |
| **B 只记合作方式 + 你点头的偏好（推荐）** | 合作方式（先问 / 直接做、回复长短、爱用的工作流）自动记；审美偏好必须你确认才记；**画面风格永远只在项目里，不自动带到别的项目** | 风格互窜被结构上挡住；审美要多点一次头 |
| C 像 Lovart 全记、由你开关 | 基本信息、合作方式、审美、常用素材都跨，项目级开关决定用不用 | 最懂你；风格互窜靠你记得关开关 |

### D3 模型底线（大脑能不能看图）

| 选项 | 做法 | 代价 |
|---|---|---|
| A 不设底线 | 现状；看图能力随用户的大脑有无 | 默认大脑（纯文本）的用户永远没有眼睛 |
| **B 大脑 + 眼睛两个模型（推荐）** | 大脑照旧任意能调工具的模型；看图动词自己调一个能看图的模型（就是 `shotVerifyJudge` 现在的做法），回人话给大脑；推荐档位不写死，由阶段 0 的尺子按模型出分数派生（`supportsImageInput` / `supportsToolCalls` 元数据 + 实测分） | 要多接一个能看图的模型；每次看都多一次调用 |
| C 大脑必须能看图 | 只允许多模态大脑 | 换掉默认大脑、排除一批便宜好用的纯文本模型 |

B 符合 P0「能力按通用场景设计、不与具体供应商耦合」：不把用户锁在某个多模态大脑上。

### D4 「看」花不花用户的钱、要不要问

看图是一次模型调用，会花用户的钱。待办里已经记着同一个问题（批量生成后自动审片默认开、用户没点过「审片」）。

**默认：**
- 你叫它看（「看看第 3 镜」）→ 直接看，回执里写明看了几张；
- 生成完自动看一遍 → **默认关**，第一次生成完问一句「以后出完要我先看一遍吗」，你的回答记进「关于你」（D2-B 的合作方式）；
- 现有批量审片的默认值随这一条一起改，待办里那条自动审片欠账由此结账。

## 不在这份路线图里

- 换聊天组件 / AI Elements / Tailwind 4（技术栈升级，另一条线）。
- 动词 × 画布状态矩阵夹具：和尺子互补，不合并；尺子量的是整条旅程。
- 对外 MCP 五个手写生成工具收编：照旧冻结，与本路线无依赖。
- Mem0 / Zep / Letta 这类记忆框架：解决的是十万级条目与向量检索，一个项目只有几十条事实，用不上（调研：Atlan、Agently、developersdigest 2026 对比）。

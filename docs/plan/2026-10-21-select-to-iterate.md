## 3 增量（只列真正的空白；每条带推荐和代价；本线不画图，样张由协调会话补）

**B-1 左侧 Agent 输入框的画布选区 chip**（09-06 拍板未实现）
- 推荐：照时间轴片段 chip 的现成做法（`useTimelineSelectionChips`：选中即投影、变了标「已变更」、× 去掉），画布选区投成同一种 `V4Chip`；长相用 E1b 的「小图 + 名字」引用 chip，灰色区分于技能 chip；超过 4 个按 C20 收成「镜03 等 5 个 ▸」。chip 是选区的**投影**，不存第二份；× 只是「这次不带」，不改画布选中。
- 代价：输入框上方多一行（选中时才出）；面板要订阅选区——不能把 #1211「画布壳不再订阅选区」的收益吐回去，订阅只能在面板里。

**B-2 框选多节点批量 + 明示上限**（Q-6 已定：暂定 12）
- 推荐：一次最多带 12 个（Flora 15、Lovart 10 之间取整），超过时 chip 写「已选 23 个，本次带前 12 个」，不静默；报价卡用 D2d 多段卡，标题写「将修改 N 个节点，各出 1 个新版本」。静默截断（G-6）由另一条修复线修。
- 代价：12 是拍脑袋的数，要用真实漫剧项目量一次再定；超上限要用户分两次发。

**B-3 请求批准档：改已有节点时，草稿放哪**（**Q-4 已定：A**。A3e 自己就两说：左格按钮叫「建节点」像 B；右格 / A3f 写「第 3 版」像 A）
- 定 **A：原节点版本栈里出一个「第 N 版 · 待生成」草稿位**（复用版本卡已有的「生成中 · 新的一版会落在这里」占位，`lab-zh-light-version-cards-new-version-pending`），点开看新旧提示词差异；确认后就在这一位上生成。理由：批量 5 个不会多出 5 张卡；和默认 2「追加到原节点」一致；用户原话「创建好那个节点」想要的是「先摆出来给我看」，A 也做到了。
- 没选的 B（原节点旁新建草稿节点 + 派生连线）的后果：批量 N 个就多 N 张卡、要连线、事后还得合并回原节点或留两张。
- 只有用户说「用这些做新的」时才建草稿节点（连线标明来源），那时就是 B 的样子。
- 草稿版是 Run 上的草稿投影（和今天报价卡同源），不是节点 `history` 里的一条：没生成就没有结果，不占版本号以外的任何结果字段；用户去掉这一项 = 草稿位消失，原节点版本不变。

**B-4 非图片节点**
- 视频：改时长 / 首帧走同一条按节点迭代；M 评论模式在视频上怎么钉点没画——第一版只走选区 chip，不进评论模式。
- 文本：画布文本节点「改短一点」= `write_node_text` 就地替换 + 撤销一次回原文，**不出版本**（文本节点没有版本栈，G-9）；报价卡不出现（不花钱）。
- 音频（第二版）：选中音频节点说「重新生成」→ chip 照常出现，Nomi 不调任何生成工具，回一句并给一步可走的路（★4「能力不可用」）。复核：手工 TTS 已经有（真截图 06），第二版缺的是 Agent 侧的计划 / 报价 / 落版本（G-8），不是「另接 TTS」。
- 代价：三种节点三种落法，回执文案要分开写（★1b）。

**B-5 左侧选区 chip 与 M 组评论线程的关系**
- 推荐：两个入口、一份请求合同。评论（底栏「评论」→ 钉点 / 框 → 线程）回复留在线程；选区 chip（选中 → 输入框）回复留在 Agent 对话。两者发出去的对象都是「节点 + 当时那一版」（同一个 `AgentContextHandle` 形状，多一个结果版本字段，G-5），落版本走同一个 owner。不把 chip 变成一条没编号的意见，也不把线程搬进面板。
- 代价：同一个节点的修改记录分在两处（线程 / 对话）；靠版本卡把两边的结果放在同一个地方看。

**B-6 多选里的角色（参考 / 目标 / 原料）**
- 推荐：不加新控件。默认「各改各的」（默认 2）；用户话里点名「参考 A 改 B、C」或「用这些做……」时由 Agent 判；判不准就用反问卡问，不猜。报价卡把角色写出来：「将修改 镜04、镜05，参考 镜03」。
- 代价：直接生成档下判错角色没有刹车兜（刹车只管连续失败和计划外）→ 角色不明时两档都先问（提示词规则 + 回执测试）。

**B-7 发出的气泡保留对象**
- 推荐：气泡从已落盘的 `contextSnapshot` 投 chip（数据已经在消息里，G-4），时间轴片段一并修。代价：小。

### ★1 用户怎么用

- 任务卡：**漫剧创作者在画布上过完一批镜头、挑出不满意的几张时，选中它们说一句怎么改，就走——新版本回到原节点的版本里等他挑。**
- 当我在画布上看到几张镜头不对时，我想选中它们直接说怎么改，以便不用在聊天里复述「镜03、镜05」，也不用一张张点生成框。
- 步骤（6 步）：① 点选 / 框选 2–5 个图片节点 → ② 输入框上方出现灰色引用 chip「镜03 · 林夏回头 等 3 个」→ ③ 打「雨再大一点，霓虹更冷」→ ④ 发送（= 确认对象），气泡里留 chip → ⑤ 请求批准档：3 个节点上各出一版「第 N 版 · 待生成」草稿（新提示词写好），报价卡「将修改 3 个节点，各出 1 个新版本」，逐项能改提示词 / 参数 / 去掉，点了的才生成；直接生成档：直接跑，刹车照旧 → ⑥ 各节点版本角标 +1、新版自动变主图；不满意就在版本卡里换回旧版（意见线程里是「放弃」= 回到上一版）。
- 不做：音频重生成、圈区域局部重绘、视频时间段、跨页面选区、超过上限的一次批量、Agent 主动调用设主图去切别的版本（主图只因新版落地自动切换，或用户自己换）。
- 已知坑：手工节点今天 Agent 改不了（G-1，不补就做不成）；文本节点没有版本（B-4）；选 9 个以上今天会被静默砍（G-6）。
- 真实任务（实现后跑，素材用仓库内真实镜头帧或用户真项目）：① 漫剧《雨夜来信》第一场 5 张镜头图，选 3 张说「雨再大一点」→ 3 个节点各 +1 版；② 选 1 个视频镜头说「改成 5 秒，首帧用镜03 第 2 版」→ 视频节点 +1 版；③ 选 2 张角色图说「用这些做一张双人海报」→ 新建 1 个节点，原两张不变。
- 指标（目标 → 信号 → 指标）：
  - 目标：不用复述对象。信号：消息里不再写节点名 / 镜号。**主指标**：带选区 chip 的消息里「Agent 实际改到的节点集合 = chip 集合」的比例 —— 量具：未验证：缺量具（建议做成走查断言 + lane 回执 nodeId 对账）。
  - **质量指标**：同一节点「再改一次」轮数中位数 —— 未验证：缺量具。
  - **护栏指标**：改到 chip 外节点的次数 = 0；模型实际收到的对象数 ≠ chip 宣称数的次数 = 0 —— 量具：`formatAgentContextSnapshot` 单测（n = 1…60）+ 新走查断言；基线：今天选 12 个只到 7 个（G-6 实测）。

6. 请求批准档：点确认之前供应商调用 0 次；改已有节点时节点数不变、每个目标节点上出「第 N 版 · 待生成」草稿（N = 出过的最大号 + 1）；卡上写明改哪几个；去掉的那项不生成、草稿位消失；说「用这些做新的」才多出 1 个草稿节点。
6b. 新版落地即主图（Q-2）；线程「放弃」→ 主图回到上一版、被放弃的那一版仍在版本卡里、⌘Z 能撤回这次放弃；下游节点不自动重跑。
6c. 反例：M3 原画的「候选」签、「接受后才设主图」不得出现。
7. 直接生成档：两个刹车照旧（连续失败 / 计划外）；角色不明时也先问。
8. 发出的气泡留 chip；冷重启后历史里 chip 还在（从落盘的 `contextSnapshot` 投出来）；时间轴片段 chip 同样留下。
9. 发送后删掉其中一个节点 → 结果暂存，撤销后落回（现有 `holdOnce`）；其余节点照常。
10. 音频节点 +「重新生成」→ 生成工具调用 0 次，回复带「打开生成框」动作。
11. 文本节点 +「改短一点」→ `write_node_text` 替换，撤销一次回原文，不出报价卡。
12. 这一类还会从哪些入口回来：时间轴片段 chip、3D-BOX 焦点标签、分镜表「交给 Agent 改」、MCP 外部宿主 `nomi_canvas_edit`（没有选区）、评论线程（B-5）——每个入口发出的对象形状一致（节点 + 当时那一版），各写一条入口测试。
- 回滚：revert 实现提交；chip 是纯投影，没有落盘格式变化；若给 handle 加了结果版本字段，旧消息缺字段时按「版本未知」显示，不报错。
- 独立验收：四类强制，另一条线按本清单核，报告链接写进 PR `## 独立验收`。

## 6 新界面三件产物（只针对增量 B-1 选区 chip）

**减法梯度（默认推 v1）**
- v1：选中 → 输入框一颗灰色 chip（名字 + 数量）+ ×；发出的气泡留同一颗。其余全不加。
- v2：v1 + 小缩略图（E1b 长相）+ 超上限那一行字。
- v3：v2 + chip 上直接切角色（参考 / 目标）+ 悬停大图预览 + 版本号。

**删除清单**

| 没放什么 | 为什么 | 要它时怎么找 |
|---|---|---|
| chip 上的角色切换 | 默认 2 已定「各改各的」，角色靠一句话说清，判不准 Agent 会问 | 在话里写「参考镜03」 |
| chip 上的版本号 | 默认改当前主图那一版，版本号多数时候是噪音 | 版本卡；过期时 chip 标「已变更」 |
| 「发送前确认对象」弹窗 | 发送即确认（默认 1） | 发出的气泡里能看到 |
| 选区 chip 的设置开关 | 不需要；不想带就点 × | — |

**卡点表**

| 问 | 回答 · 证据 |
|---|---|
| ① 他怎么知道有这功能 | 选中节点那一刻输入框里就冒出 chip（今天没有：真截图 `real-zh-light-02 / 03` chip 数 = 0） |
| ② 动手前知不知道要付出什么 | 请求批准档：报价卡逐项列出改哪几个；直接生成档：常驻提醒条 + 刹车（`lab-zh-light-direct-reminder-banner`） |
| ③ 空了 / 错了看到什么 | 空：没有 chip；错：卡上逐项写哪个失败、发没发出、下一步（D2f）；能力不可用：一句话 + 一步动作 |
| ④ 凭什么信结果对 · 错了怎么回头 | 新版本落在原节点版本卡里可比较，落地即主图；不满意在版本卡换回旧版或线程里「放弃」回到上一版，都可撤销（`lab-zh-light-version-set-primary-toast`） |

这条路几步：选中 → 打字 → 发送 →（请求批准）确认 → 看版本，共 4–5 步。能砍的一步：「打开 Agent 面板」——面板开着时选中即出 chip，不用再点画布点选钮挑一遍。

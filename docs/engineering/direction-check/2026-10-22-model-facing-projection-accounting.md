## 0. 一句话根因

给模型看的有界文本投影（选区、节点清单、边、结果 id……）各自手写一个「切掉尾巴」的编码器，没有一个共享的「不许比真实内容少却不说」的账，所以每个新投影口（发送时的选区快照 #1263、`look_at_canvas` 的选区行）都要各补一次。

## 2. 为什么这一类会一直出现

追到结构层：「有界」是预算问题，而切尾巴是预算问题最省事的答案；没有一个原语把「列了多少 / 没列多少 / 怎么读到其余」绑在编码里，所以账要靠每个投影口的作者记得写。三条体验铁律（⑩ 说的 = 摆的、⑪ 能选到、⑫ 点了 = 以为的）：不适用——这里没有意图期望、模型档案清单或可点目标，是纯文本投影的信息完整性。

本次已做的类级补强：账（total / from / listed / omitted）由施加预算的同一个函数写进文本并作为事实返回；测试梯子（1/31/32/40/256 + 翻页读尽恰好一次 + 越界 + 确定性 + 长标题）钉住不变量。**没有**做的：把「有账的有界列表」抽成全仓共享原语——只有两个实例、形状不同（JSON 句柄 vs 文本 id 行），过早抽象；列在第 6 节供拍板。

## 4. 靶子独立性检查

- 尺子 `canvasReadSelection.test.ts` 与 `census.mts` 是修复线自己写的，量的是生产排版本身，不是独立 oracle；真模型数字由 App 里的付费走查负责，本机额度不足（402）时保持 **unverified**。
- 没有「修对了反而掉分」的先例。独立验收线使用 App 走查和对应证据，不依赖修复线自带的脚本化量具。

## 5. P0：这些是我们独有的吗？现成方案有哪些

- 「有界输出 + 分页」是通用能力。现成标准：MCP 规范的列表分页——页大小由服务端决定、客户端不得假定固定页大小，服务端在响应里给出继续的位置，缺省即结束（https://modelcontextprotocol.io/specification/2025-06-18/server/utilities/pagination ）。本次做法与它同向：窗口大小由字符预算决定，响应里明说下一页要传的 `selectedFrom`，没有下一页提示即读完。
- 偏离的地方，理由是领域约束：①选区是有序的 id 集合，位置本身可读，模型直接传 `selectedFrom: 32` 比不透明游标少一层往返；②MCP 的游标主要保护「翻页途中数据变了」，本次没有，选区在翻页途中被用户改动时每页都重新写总数，模型能看出 `total` 变了（记在合同 `residual_risks`）。
- 自写登记 `gate-family`（status under-review，reviewBy 2026-10-31）：本次对 `scripts/check-verb-host-conformance.mjs` 只往已有的声明表 `TRANSLATOR_CONSUMED` 加了一行数据（`look_at_canvas/selectedFrom`），没有改门岗逻辑，也没有新增门岗。**现在换不了现成方案**：这张表检查的是 Nomi 自己的「动词声明 ↔ 宿主契约」形状，没有现成工具；**哪天换**：门岗账本（`docs/audit/2026-10-01-gate-ledger.md`）的保留 / 合并 / 降级 / 删除清单被拍板之后，按 `revisitWhen` 重评。

## 6. 接入 / 补 / 重写 / 删 对比表 + 推荐

| 选项 | 做什么 | 代价 | 风险 | 推荐 |
|---|---|---|---|---|
| 接入现成方案 | 选区翻页改成 MCP 式不透明游标 | 要在 lane 里存游标状态，动词多一个状态字段 | 状态与选区变动互相牵扯，比偏移更难测 | 否：偏移够用且无状态 |
| 补（本次已做） | 在 `projectCanvasForAgent` 里写账 + `selectedFrom` 窗口 | 已完成；模型面多一个可选参数 | 另几个有界列表（节点清单尾部等）仍无计数 | **是** |
| 重写（限一个模块） | 抽出共享的「有账有界列表」原语，#1263 与本次都改用 | 两处编码器改写，需重过两套测试梯子 | 过早抽象，两个实例形状不同 | 否：等第三个实例再抽 |
| 删 | 删掉选区行，只靠节点清单标记选中 | 节点清单本身也被预算截断，大画布上选区信息会更少 | 回归 | 否 |

## 7. 用户要权衡的核心

选区翻页用「无状态的位置偏移」（现在）还是「不透明游标」（标准做法）——前者更简单但翻页途中选区被改时只靠每页的总数提示，后者更稳但要引入状态。

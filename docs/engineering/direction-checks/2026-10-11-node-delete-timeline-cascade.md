# 方向检查：删画布节点会连带删时间轴片段，但撤销从没把片段放回来（2026-10-11，L15）

触发：`node scripts/fix-churn.mjs` 对 `workbenchStore.ts`（近 14 天 2 个 fix，这刀第 3 个）和 `canvasNodeActions.ts`（5 个，第 6 个）命中。先复盘再改；这次的改法是结构性的，不是又补一刀。

### 0. 一句话根因

「删节点连带摘掉时间轴片段」这条级联只有正向、没有反向，而且按删除入口各接各的（4 个删除入口只接了 2 个）——任何一条撤销路径都只放回节点，片段永远找不回来。

### 1. 归类表：bug → 直接原因 → 类

热点命中来自这两个文件是大枢纽，近 14 天的 fix 多数是别的类（分组、选择、生成），不是同一个 bug 反复修。真正同类的只有下面几条：

| bug | 直接原因 | 类 |
|---|---|---|
| 分镜绑定节点删除后撤销，片段丢（本次，实测 4 -> 2 -> 2） | 删节点摘片段后没记下摘了什么；分镜补偿走 `restoreGraph` 只放回节点 / 边 / 组 | 级联删除无逆操作 |
| 普通画布 Cmd+Z 删节点后同样丢片段（本次顺带确认） | 画布撤销是日志前缀重放，只管节点图，时间轴不在日志里 | 级联删除无逆操作 |
| 剪切节点、删分组连带成员后时间轴留着指向已删节点的悬空片段（本次发现） | `cutSelectedNodes`、`deleteGroup(deleteNodes)` 没调对账 | 级联按入口各接各的 |
| 撤销 / 重做 / 外部写整张图换掉节点集，时间轴不跟 | 对账只在两个删除动作里调用 | 级联按入口各接各的 |

### 2. 为什么这一类会一直出现

追到结构：两个 store（画布、工作台时间轴）各有各的数据，节点集合变化时靠「删除动作末尾手动通知一次」同步。通知是单向的（删），丢掉的东西没有地方存，而「节点回来」的入口（撤销、重做、补偿放回）本来就在另一个文件里，没人知道要通知。所以每多一个删除入口或恢复入口，就多一个会漏的地方。

铁律归属：⑫ 点了=以为的——用户点撤销，以为的是「删之前的样子」，实际只回来一半。类检查是矩阵测试 `storyboardDeleteUndoClips.test.ts`（删除入口 x 恢复入口）。

### 3. 不改结构的话，接下来会冒出什么

| 预测 | 怎么验证 |
|---|---|
| 以后新增的任何「删节点」入口（新手势、Agent 工具、导入）又漏接对账 | `door-map reconcileTimelineForDeletedNodes` 与 `rg canvas.node.removed` 的入口数对不上 |
| 节点上再挂别的依赖数据（字幕、转场之外的东西）又在撤销时丢 | 矩阵测试里加一格同款断言 |

### 4. 靶子独立性检查

测试靶子是用户可见的数据本身（片段 id / 位置 / 转场），不是实现细节；发现来源是另一条线（性能专项，真 Mac 上真鼠标）独立复现，不是同一条线写的尺子。

### 5. P0：这些是我们独有的吗

节点到片段的绑定（镜头 -> 画布节点 -> 时间轴片段）是我们独有的领域模型，自写合理（登记于领域目录）；撤销本身的日志机制已有，不重写。

### 6. 接入 / 补 / 重写 / 删 对比表 + 推荐

| 选项 | 做什么 | 代价 | 风险 | 推荐 |
|---|---|---|---|---|
| 接入现成方案 | 没有现成库管我们这两个 store 的跨域对账 | - | - | 不适用 |
| 补 | 只在分镜补偿里记片段（只修这一处） | 小 | 普通 Cmd+Z、剪切、删组、重做仍丢 / 悬空 | 否 |
| 重写 | 把时间轴并进画布撤销日志，一个事务 | 大（两个 store 的撤销栈要合） | 波及时间轴自己的撤销 | 否，超出本刀 |
| 本刀（结构收口） | 摘片段时返回摘了什么，暂存在项目级状态；所有节点集合变化（4 个删除入口、撤销 / 重做 / 外部写、补偿放回）统一过一个桥 | 中（约 120 行，新增 1 个小文件） | 暂存是会话内存，关项目即清（撤销历史本来也是） | 是 |

### 7. 用户要权衡的核心

撤销一次要不要连时间轴一起回——本刀按「要」（用户的预期）做；代价是时间轴上被撤销放回的片段如果原位置已被后来编辑占了，会滑到最近空位而不是丢掉。

## 自写登记命中：canvas-undo-journal-write-boundary

本刀没有改撤销日志机制（`canvasUndoJournal.ts` 一行未动），只在它的消费端（`canvasDocumentCommit.ts` 的 rewind / external / put-back）加了对账调用。现成方案评估：画布撤销是「事件日志前缀重放」，绑定我们自有的节点 / 边 / 组投影和生成结局叠回规则（领域约束：花了钱的结局不能被撤销丢掉），通用撤销库（如 immer patches、zundo）表达不了「撤销后叠回落地结局」；时间轴有另一套栈。所以现在换不了；真要合并两个 store 的撤销是上面「重写」一行，等时间轴也迁到事件日志时再做（届时本桥可删）。

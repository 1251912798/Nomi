# 方向检查：节点渲染树被换掉时，按下去还没抬起的点击会丢

> 触发：`GenerationCanvasReactFlowNodes.tsx` 近 14 天第 8 个 fix。这一刀只加一个标记（不改渲染结构），结构性结论交用户拍板。

### 0. 一句话根因

节点在「Suspense 兜底」和「正式渲染器」之间是两棵不同的 DOM 树，chunk 一到整张卡被摘掉重建；落在被摘元素上、按下还没抬起的点击，浏览器不再发 click，点选就丢了。

### 1. 归类表

| 提交 / bug | 直接原因 | 类 |
|---|---|---|
| Canvas Acceptance 第 2 桶 stuck-modifier 间歇红：Shift 点两张后没出多选浮条（main 收据，约 7% 复现率） | 走查在卡还是兜底时点了它，点击在兜底被换掉时丢失；失败时 pointerdown 的目标都对、只是该卡没产生 click 也没产生选中变化 | 渲染树换掉吞点击 |
| #1185 的 7 项红 | 悬停把手压在节点本体上抢点击 | 不同的类（已修，把手移到节点外） |

### 2. 为什么这一类会一直出现

- 兜底（`LightweightGenerationNode` 当 Suspense fallback）与真正的轻量档共用同一个 `data-render-mode="lightweight"`，走查 / 工具都分不出「这张卡马上要被换掉」。
- `.generation-canvas-v2-node` 选择器兜底也满足，走查等「节点出现」不等于等「节点就绪」。
- 本机证据（屏外 Electron，节点 DOM 变更记录）：失败那次，pointerdown 到 pointerup 之间两张卡先后 removed/added（兜底 → 正式）；去掉悬停把手后同样 1/30 复现，说明与 #1185 无关、早就存在。
- 体验铁律：⑫ 点了 = 以为的。人在卡刚出现的瞬间点它同样会丢一次点击（窗口很窄，丢了会再点）。

### 3. 不改结构的话，接下来会冒出什么

| 预测 | 怎么验证 |
|---|---|
| 其它「打开项目后立刻点卡」的走查在慢机器上也会间歇红 | 在 CI 记录里搜「没选中」「基线不成立」类断言，看是否集中在项目刚打开的一步 |
| 新增节点种类（新 lazy chunk）首次出现时同样丢点击 | 把某种类 chunk 延迟 2 秒后点它 |

### 4. 靶子独立性检查

尺子（走查）与产品不是同一条线写的；没有「修对反而掉分」的先例。靶子本身没错：错在它能点到一张将被换掉的卡，而这在产品里是真实状态。

### 5. P0：是我们独有的吗

React 的 Suspense / lazy 是通用能力，换树是它的既定行为；我们没有自写。现成做法：把 chunk 预加载到画布首次渲染之前，或让兜底与正式渲染共用外壳元素。

### 6. 对比表 + 推荐

| 选项 | 做什么 | 代价 | 风险 | 推荐 |
|---|---|---|---|---|
| 补（本刀） | 兜底带 `data-node-loading`；走查 `findNodeHitPoint` 按它条件等待（无标记立即通过，不加 sleep） | 一个属性、一处共享走查边界 | 产品里真人仍可能在那一瞬间丢一次点击（窗口很窄） | 现在做，先止住 CI 间歇红 |
| 预加载 | 项目打开路径先 import 该项目用到的种类 chunk，再渲染画布 | 动打开路径、要测启动耗时 | 触碰性能关键路径，需性能场景 | 作为下一步，由用户 / 协调排期 |
| 共用外壳 | 兜底与正式渲染共用同一个根元素，只换里层 | 改 `BaseGenerationNode` 与各节点根结构，面积大 | 所有节点样式 / 命中 / 选中表现 | 不推荐现在做 |
| 删 | 去掉 lazy，节点渲染器全部静态引入 | 首屏包体变大 | 首屏变慢，和已有拆包决定冲突 | 不推荐 |

### 7. 用户要权衡的核心

要不要为「卡刚出现的那一瞬间点击不丢」付出预加载（启动路径）或改节点外壳的代价；现在只补了走查侧的等待与产品侧的标记。

## 特征测试清单

- `src/workbench/generationCanvas/components/LightweightGenerationNode.test.ts`：兜底态带 `data-node-loading`，正式轻量档不带。
- `tests/ux/canvas-stuck-modifier.walk.mjs`：基线失败时打出 pointerdown 落点、选中集与截图，下一次红直接可诊断。

> 命中口径：`src/workbench/promptLibrary/` 目录 14 天内第 3 个 fix（前两个 f1068e169、9de82f660 改的是 `useUserPrompts.ts` / `PromptLibraryPanel.tsx`，都和墨色无关）。这次要改的 `PromptCard.tsx` 本身没有命中；改法是把一个墨色 token 换成另一个，不加分支、不加特例。按 CLAUDE.md P1 的例外（只因目录口径命中、文件本身没命中、改法是换）由协调会话代批，事后报用户。

### 0. 一句话根因

卡片标题下那行「类型 / 来源」用了 ink-40（设计系统给「等待生成」这类次次级灰字的档），而同一类信息在文件 chip 的「类型·大小」和详情页 `LibraryDetailMeta` 里都是 ink-60；板子只约束这行写什么、不约束深浅，所以没有东西拦。

### 2. 为什么这一类会一直出现

ink-40（L 0.68）在亮色底（L 0.985）上对比度约 2.8:1，低于小字可读线 4.5:1；ink-60（L 0.50）约 5.7:1。设计系统允许 ink-40 做「次次级」灰字，但「次次级」和「辅助信息」的界线只写在文字里，没有门岗，新卡面照抄附近的写法就会落到 ink-40。卡片元信息是用户用来区分条目的信息（图片 / 视频 / 来源），属于辅助文字，应走 ink-60。

### 5. P0：这些是我们独有的吗？现成方案有哪些

不是自写能力：用的是现成设计系统里的墨色档位，对比度按 WCAG 2.x 的 4.5:1 小字线算。

### 6. 接入 / 补 / 重写 / 删 对比表 + 推荐

| 方案 | 做什么 | 代价 |

### 7. 用户要权衡的核心

ink-40 作为文字档本身低于可读线：要不要把「次次级灰字」这一档整体收掉或调深——收掉更好读，代价是界面层次变平、要逐个面过一遍。

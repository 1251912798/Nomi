# 方向检查：拍板图认领认不出带数字的板名（2026-10-24）

触发：`node scripts/fix-churn.mjs` 命中自写登记 `gate-family`（状态 under-review，30 天内第 2 个 fix 即命中）；`scripts/check-board-parity.mjs` 文件本身没命中。改法是换（板名定义收成一份，认领行与磁盘上的板文件共用），不新增分支或特例 → 按 P1 例外由协调会话代批（2026-10-24），事后报用户。

### 0. 一句话根因

认领行的板名写法（`[A-Za-z]+`）和磁盘上板文件名的真实写法各管各的，没有任何测试拿磁盘上的板去喂认领解析，带数字的板名一出现就成了「有板、认领不了」。

### 1. 归类表：bug → 直接原因 → 类

| 提交 / bug | 直接原因 | 类 |
|---|---|---|
| F1 图标 PR 推送被 `check:pr-judgement` 拦「拍板图没认领」 | `CLAIM_LINE` 的 `[A-Za-z]+` 认不出 `IconsF1` | 同一个概念（板名）在两处各写一份定义 |
| 潜伏：`ComposerB3`、`Director3dbox`、`SpendCardQ1` | 同上；#1269 在严格口径生效前开的 PR，没被拦 | 同上 |

### 2. 为什么这一类会一直出现

板名只出现在两处：板文件名（`<板名>.board.json`，`findDatedBoards` 取文件名）和 PR 正文的认领行（`CLAIM_LINE`）。认领行的正则是照最早 12 张纯字母板写的，后来的板名带数字，两处定义从没被拿来对过。

### 3. 不改结构的话，接下来会冒出什么

- 下一张带数字的新板认领照样失败，推送被拦，实现线只能改板名（板文件是合同，要协调确认）或拿例外顶过去（不诚实）。
- 有人把认领行写成 `- Icons F1:` 之类绕过，合并前扫描对不上板。

### 4. 靶子独立性检查

改的是解析规则本身，测试读的是磁盘上真实的板文件，不是测试自己造的样例；新板一落盘就进测试。

### 5. P0：这些是我们独有的吗？现成方案有哪些

`## 拍板图` 认领行是拍板图合同的领域格式（设计流程第 2 步「清单是实现合同」），没有现成库解析它，只能自己写。`gate-family` 整族门岗要不要换成现成规则引擎，是登记表那条的评估，不在这一刀的范围。

### 6. 接入 / 补 / 重写 / 删 对比表 + 推荐

| 选项 | 做法 | 代价 |
|---|---|---|
| 接入现成方案 | 无适用的（见 §5） | — |
| 换（推荐，已做） | 板名定义收成一份 `BOARD_NAME`，认领行与板文件共用；node-test 拿磁盘上每一张板喂认领解析 | 一处正则 + 一条测试 |
| 改板名 | 把带数字的板都改成纯字母 | 板文件是合同，改名要协调确认、牵动引用；下一张新板照样会撞 |

### 7. 用户要权衡的核心

没有要权衡的：门岗的一处写法错，修法唯一，事后报用户。

# 方向检查：选区快照省略时的读法指路

## 触发

真实模型抽样显示，选区快照的省略说明会改变 Agent 的下一步：画布节点已经有能读回完整选中节点的读法，但统一的“缩小或分批”提示把 Agent 引向了另一条路。快照专用量具还把问题写成了自证式的固定回答，因此不能代替真实行为验收。

## 根因

发送时快照和实时画布读法各自表达同一批选区，却没有一个按类型声明“看不全时去哪读”的单一来源。于是模型把画布的省略当成不可恢复，用户被要求手动分批；时间轴片段和素材仍没有带选中标记的读法，继续需要用户缩小或分批。

## 决定

省略说明按 `omittedByKind` 中实际出现的类型派生：画布节点指向无参数的 `look_at_canvas`，说明节点行带有选中标记、可读到全部选中节点，并要求比较它报告的选中数与快照 `total`；数量不同就告诉用户发送后选区发生了变化。没有带选中标记读法的类型保留“请用户缩小选区或分批发送”。类型到读法的表只放在快照模块旁边，说明文字和投影预算长度都从它生成，避免模型面 schema 继续膨胀。

快照专用档删除。快照账由共享投影单测固定，真实模型量具只保留画布读法的主档；零花费演练只证明主档能跑通，不把夹具对固定答案的自证当成 Agent 行为证据。

## 拍板

用户原话：「#1263 选 A（画布看不全让 Agent 调 look_at_canvas 读全，时间轴/素材仍请用户缩小）」。

## 后续真实抽样与拍板

同一付费量具在上一版按类型指路的构建上仍为 0/5：五轮中四轮没有调用 `look_at_canvas`，另一轮虽然调用了它，却把两个未选中的视频也列进了回答。对照构建在同一量具上为 5/5。根因是快照仍然把画布选区列了一部分并附上总数；模型把这半份列表当成选区正本，说明文字没有改变这个行为。

用户原话：「#1263 按 B′：画布选区放得下就全列，放不下就一个不列、只给总数和读法（look_at_canvas）；时间轴/素材照旧请用户缩小。再跑同一付费量具，主档 5/5 才合。」

## 这一版交回后协调核对（2026-10-25）

- 发现：编码器在最丰富那一档列不全时，没先试更省的档，就把画布整类不列了。更省一档本来放得下全部的选区（40 个节点只是副标题长、20 个导演镜头只是标题长）也一个不列，和拍板的「放得下就全列」相反；对应的两条旧单测被改成了期望 0。
- 改正：先让每一档都试一遍全列，全都放不下，才把有完整读法的类整类不列，剩下的类照原阶梯列。两条旧单测恢复为期望全列，另加一条混选（画布 30 + 时间轴 5，首档放不下、次档放得下）必须全列。三条对改正前的编码器跑都红，改后绿。
- 同时改正说明里的核对口径：look_at_canvas 数出的选中数，和 omittedByKind 里画布这一类的数比，不和整份快照的 total 比。混选时 total 还含别的类，拿它比必然对不上，模型会对用户谎报「选区变了」。
- 付费量具的问法、场景、评分和构建标记都没动。量具里选中的 40 个节点在最省档也放不下，照样走「整类不列、去读画布」这条路。

## 改正后的付费复跑与判分改法（2026-10-25）

- 同一付费量具在改正后的构建上跑了 5 轮：
  - 5 轮都无参数调用了 `look_at_canvas`，都读全了 40 个选中节点，列出来的都正好是选中的 20 个视频；
  - 旧判分只记 1/5。其余 4 轮在列表之后补了一句「画布上另有 2 个视频没被选中」，旧判分按「答话里出现过标题」算，把这句里的两个标题记成了多列；
  - 上一版那一轮「读了画布却多列 2 个」也是同一回事。
- 判分改成：答案 = 列出来的条目（编号 / 项目符号 / 表格行）+ 没明说「没选中」的散文行。
  - 列表项上标了「未选中」，照样算多列；散文里说干扰节点也选中了，也算多列。
  - 单测先红后绿：「列表全对 + 末尾明说没选中」和「整段话答全 + 明说没选中」两条，旧判分下红，新判分下绿；「列表里混进没选中的」和「散文里误认干扰节点」两条，新旧判分都判失败。
- 用新判分重算三份已有证据，只重读答话，不再花钱：
  - 对照构建 5/5 → 5/5；
  - 上一版 0/5 → 1/5，只有调了读画布的那一轮对；
  - 这一版 1/5 → 5/5。

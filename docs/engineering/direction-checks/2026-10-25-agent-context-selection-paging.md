# 方向检查：Agent 上下文快照放不下时，模型怎么拿回剩下的选区（#1263 第 3 轮）

> 触发：同一条线派第 3 轮（模板「触发」第 4 条，人工判）。`node scripts/fix-churn.mjs` 对 `electron/shared/agentContextSnapshot.ts` 没命中热点。
> 概念：`agent.context-snapshot-projection`；新增一个读动词。

### 0. 一句话根因

选区放不下时，模型要靠工具把剩下的拿回来。前两轮都在问「这类东西有没有读工具」，可真正该问的是「有没有工具能把用户点发送那一刻选了哪些读回来」。完整选区本来就随每条消息送进了主进程，缺的只是一个读它的口。

### 1. 归类表

| 轮次 | 直接原因 | 类 |
|---|---|---|
| 第 1 轮：放不下就列最长前缀 + 记账 | 真模型拿到半截列表，当成全部，跳过 `look_at_canvas` | 给模型一份「看起来完整」的部分选区 |
| 第 2 轮：有读工具的类整类不列 | 「有读工具」被当成「读得回选区」；`read_timeline` 读整条时间轴，`look_at_media` 搜素材库，都不返回选区 | 拿掉了模型读不回来的选区 |

### 2. 为什么会一直冒

- **可恢复性挂错了地方**：第 2 轮把它挂在各个领域读工具上，在投影层手抄了一张「类 → 工具」表。
  - 领域读工具读的是实时状态，不是「发送那一刻的选区」，用户中途换个选择就对不上。
  - 每多一种可选的东西，就要回头补一遍表和工具。
- **完整选区其实一直在**：完整快照随请求进了主进程（`electron/agentLane/laneDesktopInput.ts` 收的 `contextSnapshot`），投影只是给模型看的那一份（`agentContextSnapshot.ts` 头注释：「The full immutable snapshot stays on the Host request」）。
- **对应铁律 ⑫「点了=以为的」**：用户框选一批再让 Agent 处理，预期 Agent 处理的正是这一批。

### 3. 不改的话会冒出什么

| 预测 | 怎么验证 |
|---|---|
| 时间轴全选（超预算）后问「给这些片段加字幕」，模型读完整条时间轴，仍不知道选了哪些 | 单测：120 个 `timelineClip` 句柄 → 第 2 轮输出 `listed=0`，只给 `read_timeline`；`read_timeline` 返回里没有选区 |
| 画布 40 个节点 + 3 个时间轴片段混选：3 个片段本来放得下，也被一起拿掉 | 单测：混选 → 第 2 轮 `listed=0` |
| 发送后用户改了画布选择，模型按 `look_at_canvas` 读到的是新选择 | 交互测试：发送后改选择，再读 |

### 4. 靶子独立性

付费量具（`look-at-canvas-selection-real.paid.mjs`）只量画布选区，量不到时间轴；这个缺口是协调审代码查出来的。量具本身不用改，只要把「调了哪个工具」分开记数。

### 5. P0：是不是我们独有的、有没有现成做法

列表太长、放不进模型上下文时，通用做法是分页：给游标，按需往下翻（MCP 规范对列表类操作就是这么做的：不透明 `cursor` 入、`nextCursor` 出——实现线在设计卡 ★0 里实查规范原文并给链接）。我们独有的只是「选区快照」这份数据本身（画布、分镜、时间轴的选中项）。

### 6. 对比表 + 推荐

| 选项 | 做什么 | 代价 | 风险 | 推荐 |
|---|---|---|---|---|
| 接入通用做法：按页读这次发送时的选区 | 放不下就一个不列，只写按类计数和读工具名。新增一个内部 read_selection 动词，按游标分页读本条消息随附的那份快照；它放在 context 延迟组，由常驻 nomi_request_tools 解锁。删掉第 2 轮的「类 → 工具」表和最长前缀分支。 | 中：一个新读动词（模型可见契约，R5.5）+ 投影规则 + 真模型数字 | 多一个工具，模型要学会在 omitted > 0 时去翻页；靠真模型数字验证 | ✅ |
| 补：只对画布、文稿整类不列 | 其余类退回最长前缀 + 记账 | 小 | 时间轴超预算时仍是半截列表（第 1 轮的老问题） | ✗ |
| 给领域读工具各加实时选区读法 | 时间轴读工具加选区参数；以后每种可选的东西各补一遍 | 中 | 读的是实时选区，发送后换选择就读错；类型一多就漏 | ✗ |
| 原样合 | 第 2 轮照合 | 无 | 时间轴超预算时丢选区，属于回归 | ✗ |

### 7. 用户要权衡的核心

多一个「翻页读选区」的工具，换来所有类型一次覆盖、读到的就是发送那一刻的选区；代价是模型可见的工具多一个，要用真模型数字证明它会用。

## 拍板

用户 10-25 选了「按页读这次发送时的选区」。另外，素材类（image / video / audio）现在没有任何生产者会把它们放进快照，不单独做；以后有了生产者，自动被这个读动词覆盖。

## 特征测试清单

- 已钉：`electron/shared/agentContextSnapshot.test.ts`、`src/workbench/ai/resident/residentContextSnapshot.test.ts`（第 2 轮规则，含 40 / 256 节点 census）。
- 第 3 轮要补：
  - 120 个时间轴片段超预算 → 一个不列，各页拼起来等于快照；
  - 画布 40 + 时间轴 3 + 文稿 1 混选 → 一个不列，按类计数对，各页拼起来顺序一致、不重不漏；
  - 坏游标、没有快照 → 机器可读的错误；
  - 同一快照投影两次文本相同（KV 稳定）。

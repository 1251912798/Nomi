# 方向检查：拍板图板名的两份定义（check-board-parity，2026-10-24，交用户拍板）

触发：`scripts/check-board-parity.mjs` 近 14 天第 4–5 个 fix（`39540ff59`、`16a65f69d`、`a29ffd6f1`、`cef70efdb`），文件本身命中热点，不在协调代批口径里。

### 0. 一句话根因
「板名」有两份定义：找板按文件名（`<板名>.board.json`，什么字符都行），PR 正文认领行用正则 `([A-Za-z]+)` 只认纯字母。带数字的板名（`Director3dbox`）认领行被静默丢掉。

### 1. 归类表
| 现象 | 直接原因 | 类 |
|---|---|---|
| 导演台修复 PR 的 `check:pr-judgement` 报「改了界面，但既没认领也没写例外」，其实正文写了 `- Director3dbox: notice.staging-attach, …` | `CLAIM_LINE` 只认字母，`parsePrBoardClaims` 返回 `[]` | 同一个名字两份定义、各写各的规则 |

### 2. 为什么会一直出现
找板、认领、清单校验各自解析板名，没有一处说「板名长什么样」。新板命名一换规则（数字、连字符），总有一处认不出，而且是静默的。

### 3. 不改结构，接下来会冒出什么
1. 任何带数字或连字符的新板，认领都会被吞，PR 被挡。
2. 有人为了过门岗改板名或写「例外」，认领记录失真。
3. 只放宽正则，下次清单校验或 `--reextract` 的另一处解析还会对不上。

### 4. 靶子独立性
只有这一个现象，但同形状的解析点不止一个（找板、认领、日期目录同名板），要一起收。

### 5. P0
自写登记条目：`gate-family`（门岗家族，状态 under-review）。门岗是我们自己的工具，没有现成库；做法是「一个名字一份定义」，不需要新依赖。本次先完成结构性收口；在 2026-10-31 reviewBy 前评估接入现成视觉回归 / 清单校验方案，若能覆盖“板名解析 + 清单认领”再迁移。

### 6. 对比表 + 推荐
| 选项 | 做法 | 代价 |
|---|---|---|
| **换（推荐）** | `board-extract.mjs` 导出唯一的 `BOARD_NAME` 规则，找板（文件名）和认领行都用它；加一条测试：仓库里每张真实的板，名字都能被认领行解析出来 | 两个文件、十来行 + 一条测试 |
| 补 | 只把 `[A-Za-z]+` 换成 `[A-Za-z][A-Za-z0-9]*` | 一行，但两份定义还在，下次换命名规则再坏 |
| 绕 | 板改名成纯字母 | 不改门岗，记录和板文件对不上，掩盖问题 |

推荐「换」：改动量和「补」差不多，但以后新板怎么命名都不会再被静默吞掉。
用户 2026-10-24 拍板：收成一份定义

### 7. 用户要权衡的核心
这个门岗文件两周里已经修了 4 次。这次是「把板名收成一份定义」（结构性，修完就不会再出这类问题），还是先只改一行正则让导演台的 PR 过（快，但同类问题还会回来）。推荐收成一份定义。

## 特征测试清单
- 仓库里每张 `*.board.json` 的名字，放进认领行都能解析出来。
- `Director3dbox`、纯字母、带连字符的名字各一条正例；空名、只有数字开头的各一条反例（如果规则不允许）。

## 结局（2026-10-24 协调补）
本 PR（#1315）里的这份修法（`f1c4391dd`）没有落地。同一天 #1324 把同类修法先合进了 main：板名规则在 `scripts/check-board-parity.mjs` 里收成一份定义（`BOARD_NAME_PART`），认领行由它生成，磁盘上每一张板（含 `Director3dbox`）的名字由普查测试对它核——仍是上面「收成一份定义」的拍板。为了不留两份并行实现，#1315 撤回了自己这份三个脚本的改动，以 main 为准，见 `2026-10-24-board-claim-name.md`。两份的差别只在报红的位置：这份在门岗运行时点名非法板文件名，main 那份在普查测试里报红，两处都在 CI 拦下。

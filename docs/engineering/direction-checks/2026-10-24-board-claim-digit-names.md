# 方向检查：拍板图认领行的板名语法

> 触发：提交钩子的 `fix-churn` 命中自写登记 `gate-family`，近 30 天已有 89 个 fix；本次是第 90 个。任务书要求修复 PR #1322 的带数字板名认领失败。这个方向检查记录为什么本次仍修共享解析边界，并把类级普查一起交付。

## 0. 一句话根因

拍板图认领行的共享正则只写了「字母」，没有写仓库真实板名的「字母开头、后续字母或数字」不变量；门岗因此静默丢掉带数字板名，后续判据无法看到它。

## 1. 归类表

| 提交 / bug | 直接原因 | 类 |
|---|---|---|
| PR #1322 | `CLAIM_LINE` 使用 `([A-Za-z]+)`，`IconsF1` 未进入 `parsePrBoardClaims` | 共享门岗解析边界与真实板名集合脱节 |
| 本提交 | 同一正则需要接受 `ComposerB3`、`Director3dbox` 等现有板名 | 同上；通过普查测试封住未来同类 |

## 2. 为什么这一类会一直出现

这个判断属于交付门岗的仓库规则，不是 Nomi 产品领域。它一直出现的结构原因是：解析器的语法与 `docs/design/boards/` 文件名没有一条自动连接，测试只覆盖了 `Main` 这类纯字母样例，新增板名可以合法落盘，却在 PR 正文里被静默忽略。类根因落在铁律 ⑫「点了=以为的」：作者写下认领行，以为合并扫描会关联到清单；解析结果却没有这条 claim。最小证据是旧实现对三条数字板名返回 `[]`，以及 `check-board-parity.node-test.mjs` 的新普查。

| 铁律 | 结论 | 最小证据 |
|---|---|---|
| ⑩ 说的=摆的 | 不适用：不涉及生成参数或草稿字段 | — |
| ⑪ 能选到 | 不适用：不涉及模型档案或参数入口 | — |
| ⑫ 点了=以为的 | 适用：PR 作者写的认领必须进入门岗实际判定 | `scripts/check-board-parity.node-test.mjs` 数字正例、非法字符反例、真实板名普查 |

## 3. 不改结构的话，接下来会冒出什么

| 预测 | 怎么验证 |
|---|---|
| 新板名继续带数字时，合并前扫描又把有效认领当成没有认领 | 普查测试在 `docs/design/boards/` 新增该板后直接变红 |
| 另一个消费者自行复制正则，两个门岗对同一行给出不同结论 | `rg -n "CLAIM_LINE|parsePrBoardClaims|checkPrBoardClaims|checkBoardClaim" scripts` 与 door-map 复查 |
| 有人把连字符或下划线塞进板名，语法被无意放宽 | 非法字符反例应保持只解析合法行；新文件名必须先经过普查测试的显式决定 |

## 4. 靶子独立性检查

解析测试由现有 `node:test` 门岗测试执行，合并前扫描是另一条真实消费路径；两者都调用生产 parser，不依赖测试源码字符串匹配。没有评测 oracle 或分数回滚记录。旧行为已先用最小 Node 片段钉住：三条数字板名的解析结果均为 `[]`。

## 5. P0：这些是我们独有的吗

通用正则和 Node `node:test` 都是现成能力，本次没有新自写库。板名允许哪些字符是仓库交付领域约束：它必须和真实 `docs/design/boards/**/*.board.json` 文件名一致。没有第三方库能替代这个仓库本地的 claim 语义；引入 schema 库只会增加依赖，不能回答哪一个清单存在或元素是否已实现。

## 6. 接入 / 补 / 重写 / 删 对比表 + 推荐

| 选项 | 做什么 | 代价 | 风险 | 推荐 |
|---|---|---|---|---|
| 接入现成方案 | 不适用：通用 parser / schema 库不拥有本仓库板名和清单语义 | 引入依赖与适配层 | 仍要维护本地规则 | 不选 |
| **补共享边界** | 把 `CLAIM_LINE` 改成字母开头 + 字母数字，并在同一门岗测试里普查全部真实板名 | 一处正则 + 类级测试 | 低；未知板仍由语义校验拒绝 | **推荐，本提交** |
| 重写 | 重写整套 PR 正文 parser | 影响所有正文判据 | 改变已验证的分节、元素 id 和异常语义 | 不选 |
| 删 | 删除板名认领门岗 | 改动最小 | UI 改动失去设计合同保护 | 不选 |

## 7. 用户要权衡的核心

本次只让共享门岗如实识别仓库已经存在的数字板名；若未来要支持连字符、下划线或非 ASCII 板名，应先由用户拍板文件命名规范，再改语法和普查，不在这次悄悄放宽。

- `node scripts/door-map.mjs --read=CLAIM_LINE,parsePrBoardClaims,checkPrBoardClaims,checkBoardClaim --roots=scripts`：确认所有生产消费者仍走共享 parser。

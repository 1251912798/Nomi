# 方向检查：内联白板的对象尺寸与浮层跟踪（RW，2026-10-17）

触发：`node scripts/fix-churn.mjs` 对 `WhiteboardDrawingTool.tsx`（近 14 天第 4 个 fix）、`src/design/AnchoredPopover.tsx`（第 5 个，目录 `src/design/` 第 9 个）、概念「按钮点开的浮层放在哪儿」（第 7 个）命中。本刀来自 #1189 的审查报告 F2 / F7。

## 0. 一句话根因

同一个几何事实有两个来源、谁都不对另一边负责：白板文字的「大小」创建时按字数估一次存进状态，而真正画出来的大小由 Leafer 排版决定；浮层的「位置」靠一个常开的逐帧轮询去追锚点，而不是在锚点真的动了的时候再追。

## 1. 归类表：bug → 直接原因 → 类

| 提交 / bug | 直接原因 | 类 |
|---|---|---|
| F2 长文字可见部分点不中（中文 128×48、英文 288×48） | `placeText` 用 `max(120, 字数×字号)` 估宽、高固定一行；改文字 / 字号不重算；Leafer 子文本按固定宽度换行溢出，父 Box `hitChildren:false` 只剩原边界 | 尺寸有两个来源：存下来的估计值 vs 排版实测值 |
| FB-20261012 画板尺寸浮层停在旧位置盖住工具条 | 浮层只听自己的 resize / scroll，不知道锚点被画布变换挪走 | 位置只在「这几个事件」里更新，漏一类运动源就漂 |
| F7 逐帧读布局 | 为补上面那条，`autoUpdate({ animationFrame: true })` 在面板开着的每一帧读 `getBoundingClientRect`，哪怕什么都没动 | 补法用「常开轮询」换「不漏」，空闲也付费 |

## 2. 为什么这一类会一直出现

追到表示层：两处都把「派生量」当「存储量」来管。文字尺寸是排版的派生量，却由多个写入口各自估计；浮层位置是锚点矩形的派生量，却靠订阅事件源的清单去逼近，清单永远补不全，于是每漏一类（resize → 滚动 → 画布平移 / 缩放 → 节点拖动）就出一条 bug，每条 bug 的补法都是再加一个源或干脆常开轮询。

铁律：落在 ⑫「点了 = 以为的」——用户点文字最后一行，以为选中文字，实际点到下层图片；用户开着浮层移动画板，以为浮层跟着走。

## 3. 不改结构的话，接下来会冒出什么

| 预测 | 怎么验证 |
|---|---|
| 字号、换行、字体回退变化时，文字命中框与可见范围再次分叉 | 走查「长文字尾部可点、可拖、可导出」断言（`tests/ux/whiteboard-refactor.walk.mjs`） |
| 空闲时开着面板，逐帧读布局使低配机器的主线程长期不空闲 | 性能场景 `inline-whiteboard-idle-panel` 的空闲读矩形次数 / 忙碌占比 |
| 又一类运动源（容器 CSS 过渡、侧栏展开动画）让浮层漂 | 走查动态锚点矩阵（width / height / 滚轮 / 拖节点）+ `src/design/anchorMotion.test.ts` 的运动源矩阵 |

## 4. 靶子独立性检查

- 走查与断言和实现是同一条线写的，但文字用的是导出像素的独立读法（读保存的 PNG 数红色像素），浮层用的是 `elementFromPoint` 命中可达，不是只读 rect。
- 无「修对了反而掉分」的先例。
- 性能基线是本刀新登记的，预算标 `proposed`，由协调确认。

## 5. P0：这些是我们独有的吗？现成方案有哪些

- 文字排版 / 测量：不是独有。Leafer 的 `Text` 自己就排版并给出盒子（`boxBounds`），已接，不再自己估。
- 浮层跟踪：不是独有。`@floating-ui/dom` 的 `autoUpdate` 已在用；它对 transform 运动没有事件源，官方给的只有 `animationFrame`（常开）。在它外面补的只是一个「祖先的 style / class 变了才开几帧」的运动门，属于接线，不是自写定位。
- 自写登记：无新增条目。

## 6. 接入 / 补 / 重写 / 删 对比表 + 推荐

| 选项 | 做什么 | 代价 | 风险 | 推荐 |
|---|---|---|---|---|
| 接入现成方案（文字） | 尺寸直接取 Leafer `Text.boxBounds`，写入口统一走 `applyTextChanges` | 改 4 个文件 | 字体回退差异几像素 | 是（删估计公式，同提交） |
| 接入现成方案（浮层） | 保留 `autoUpdate`，`animationFrame` 关掉，用 MutationObserver 观察锚点祖先的 `style` / `class`，运动期间才逐帧、静止几帧后收工 | 约 40 行 | 运动源不改 style / class 时漏跟 | 是，且用动态锚点走查矩阵兜底 |
| 补 | 再给文字加一次「点击后重算」或给浮层多订阅几个事件 | 小 | 继续两个来源 | 否 |
| 重写 | 自己写文字排版 / 定位 | 大 | 违反 P0 | 否 |
| 删 | 去掉文字对象或面板跟踪 | 丢功能 | 违反「改设计不能丢功能」 | 否 |

## 7. 用户要权衡的核心

浮层跟踪要不要为「所有运动源都不漏」付出常开的每帧成本，还是接受「只在祖先样式真的变了时才跟」——本刀选后者，漏跟的风险由动态锚点走查矩阵兜底。

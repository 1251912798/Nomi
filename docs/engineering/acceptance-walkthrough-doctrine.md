# 验收走查纪律（2026-09-09 用户拍板：「以后就按今天这种做测试流程，以前的测试太蠢了」）

> 谁读：任何要给用户看「这功能好了」的人或执行体。它是 R13 / R16 / R30 的**执行版**：R16 说要带真实任务跑闭环，这里说**怎么跑才算数**。
> 触发：功能交付前、主线合并门、发版前；以及任何 Agent / 工具 / 提示词 / 模型档案改动。

## 一、为什么以前的测试「太蠢」（当天现场抓到的四种假）

| 假在哪 | 当天的样子 | 为什么测不出东西 |
|---|---|---|
| 假输入 | 直接往 store 灌状态、走 E2E 桥、喂夹具 JSON、重开窗口绕过卡点 | 用户从来不这样用；灌进去的状态跳过了所有会坏的那一步 |
| 假流程 | 把 Agent 当流水线里的一个「分镜站」，整轮只发一句「拆分镜」 | Agent 的输入分布 n=1，工具写对率算不出分布 |
| 假省钱 | 为省额度 dry-run / loopback 夹具代替真模型、一件真出都不做 | 夹具对「模型面对各种说法会怎么做」零信息；反复重跑才是最贵的 |
| 假顺序 | 按界面面（画布/素材库/设置）铺 case，先翻提示词库再谈 Agent | 从机制清单起头，不从用户会做什么起头（违反 D1） |

## 二、规则（六条，缺一不算验收）

1. **像人一样点**：一个窗口从头到尾；只许界面动作（点、敲、滚、悬停、按界面状态等）；模型在下拉里选、剧本逐字敲；禁灌状态、禁桥、禁夹具输入、禁 `evaluate` 改状态、禁重开窗口绕过卡点。卡住 > 3 分钟无界面变化 → 截图记下，跳下一条，不等、不修补、不重跑。
2. **测 Agent = 先写「用户会说的话」表**：≥ 20 句，覆盖 意图（只读 / 能力自述 / 局部改 / 重排 / 改画幅 / 改文稿 / 建节点不生成 / 真出 / 费用问答 / 被阻 / 缺前提）× 措辞（口语 / 命令 / 英文）× 模糊（「感觉不对」）× 长短（长粘贴重拆）× 中途插话 × 收尾。每句写「期望的首个动作」和「证明什么」。**Agent 面的 case 数 ≥ 其他面之和**，并且排在界面面之前。
3. **每功能少量真出**：图 2 张、视频 2 段、分镜试拍 1+2、Agent 回合若干、MCP 1 次、导出 1 次、冷重启 1 次。封顶写**件数**不写金额；任务书写死「不核实账单、不问单价、不停」；确认框没金额本身记一条。
4. **一次扫全，再批修，只复扫一次**：走查改「记录并继续」，所有面跑完出总账；按根因聚簇、每簇一条通用修法、并行修；复扫一次；复扫新簇为零或只剩低严重度 → RC。中途不派修。
5. **每一屏三个数**（信息密度，R2）：这一屏有多少行对用户没有行动价值；同类条目连续重复几次、有没有折叠；失败/警告有没有说「接下来做什么」。折叠方向：**用户输入默认收起、Agent 回答默认摊开、过程默认收起**。
6. **数字进 PR**（R30）：首调写对 n/d、回合成功 n/d、平均切组次数、审批次数、裸 Markdown 次数、首字耗时；截图是证据不是结论，主会话逐张亲眼看。

## 三、任务书模板要点（派 Codex 走查时照抄）

- 开工三行头写死：目录、**开工第一步自己启动 X（用 profile Y）**、结束于哪份报告。禁令要限定范围（「测试过程中不许关了再开」），不写无范围的「禁 X」——Codex 把禁令当硬限，无范围禁令 = 原地退出。
- 表格：每句/每步 = 动作 / 截图前后 / 界面反应 / 耗时 / 密度三数 / 「人会怎么理解这一屏」一句。
- 报告 ≤ 25 行 + 截图路径清单；模型答复原文只截 2 行。

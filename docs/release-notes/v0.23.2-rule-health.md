# v0.23.2 规则体检

晋级前的体检记录（`docs/release-process.md` §5）。范围：这一批逃逸账本里的问题，只有两件：视频在上游做好了却取不回（issue #1213），以及 Agent 把可选参数写成空值、点「生成」被整次拒掉。写法实事求是：拦住了就写拦在哪一档，没拦住就写没拦住、补了什么。

档位按强弱：删掉 > 结构上做不出来 > 门岗自动拦 > 文字规则。

## 一、视频在上游做好了却取不回（#1213，账本 `USER-20261016-video-result-not-retrieved`）

类根因：「上游这次成没成、结果在哪、没取到卡在哪一步」在两台引擎和渲染层各有一份读法，状态词表有四份、各漏不同的词；中转通道的查询合同没有以真实返回形状为准的唯一 owner。

| 同类问题还能从哪里回来 | 现在拦在哪一档 | 证据 |
| --- | --- | --- |
| 上游状态词多一种拼写 / 认不出的词 | **删掉**：三张私有状态词表已删，只剩 `shared/taskStatus` 一张；认不出 = unknown，绝不当失败 | `check:vocabularies`（门岗）守「不许再长第二份」；词表基线本批自动收缩 4 项 |
| 结果地址在哪、读到回显的参考图 | **结构**：状态与地址的读点只剩 `readTaskResponse`，先合同、再通用规则（核媒体类型、排除回显）；落盘关口再按任务期望类型核字节，期望类型在每扇写入口由类型必填 | `taskResultReading.test.ts`、`retrievalKindGate.test.ts`、`generatedOutputKindGate.test.ts` |
| 新增一条视频查询通道 / 新模型 | **门岗**：普查测试遍历内置 108 条视频查询映射，每条过同一组真实返回夹具；成功状态必须由状态词本身认出 | `videoQueryContractMatrix.test.ts`（进默认测试车道） |
| 中转对查询路由回了「不一样」的错误被误切原生通道 | **结构 + 门岗**：只有探测拿到原生合同自己的「任务不存在」回答才走原生；无证据的已切模型启动时降回通用 | `nativeEndpointProbe.test.ts`、`relayNativeWireReconcile.test.ts` |
| 取回失败原因被吞掉 | **结构**：「可找回」落地时保留最后一次失败原话，面板与失败卡共用一套三件套 | `NodeRecoverableReport.test.tsx`、`nodeRunOutcome.test.ts` |
| 重新取回再扣一次钱 | **结构**：重启后「重新取回」只重建查询、不提交；五种取回异常真落盘后新进程读回 | `retrievalRestartOnDisk.test.ts` |

没拦住的（如实写）：
- 这位用户的中转当时具体回了什么没有证据（面板和存档都吞了原因），根因按时序和代码证据推定为「查询一直报错」，未经真中转复现。
- OpenAI-video 形状不带地址、要再鉴权取内容，只做到诚实失败，不支持取回。
- 已经被吞掉原因的旧「可找回」节点，原因找不回来。
- 跨真实进程重启的「对服务商账单只有一笔」没有统一网络账本，要真付费验收（协调线在跑）。
- 读取层在两种情形下仍可能交出回显地址（无扩展名且无请求记录；生产不可达的无上下文直调），由落盘关口按字节拒收兜底；这是「门岗拦」，不是「做不出来」。

## 二、Agent 把可选参数写成空值，点「生成」整次被拒（`seed: null`）

类根因：参数值的判据有两个时刻、一个入口：起草时只判身份、确认时才判值；模型惯用 null 表示「不设」，免费演练夹具的大脑从不演这种写法，所以拦不住。0.23.1 同一段代码，属「用不了」类。

0.23.2 带的两块（热修只带最小面）：

| 环节 | 档 | 说明 |
| --- | --- | --- |
| 空值语义 | **结构**：只有 `compileParameters` 一处定义；null / undefined 按没填，必填写空按缺必填点名，字符串冒充数字照拒 | 普查单测遍历全部模型档案、逐个可选参数写 null，目录增长自动覆盖 |
| 确认被拒说不出原因 | **结构**：结果带 `reason`、`field`、失败类 `parameter_rejected`，卡上点名参数 | `agentPanelSpendRejected.e2e.test.ts`、`spendCardFailure.test.ts` |

没拦住 / 没带的（如实写）：
- **起草时校验没带进 0.23.2**：起草仍只核「模型 + 模式」，坏值（比如 `seed: "abc"`）还是等到点「生成」才被拒。0.23.2 靠「空值按没填」消掉最常见的一类，其余坏值只是改成了「说得出是哪个参数」，仍出现在付费卡已摆出之后。这部分在 main（#1244）已前移，随 0.24 发。
- **逃逸账本里没有这一条**：它是 10-18 真付费走查发现的，不是用户来信，目前 main 与 #1244 分支的账本目录都没有对应条目；建议协调补一条，否则结账「必须挂结构性预防」的机制看不到它。
- 免费演练夹具的大脑不写 null 的缺口，在 main 已补（夹具大脑带 `seed:null`），0.23.2 分支没带。
- 0.23.1 的付费卡仍是右上 ×、没有「取消」按钮；main 已删 ×，文案中凡指向 × 的两句只对 0.23.x 成立，合回 main 时以 main 为准。

## 三、门岗只会误报的（本批实测）

- 在 Windows 上，`gates:contracts` 里 12 道在 v0.23.1 干净基线上就红（路径用 `URL.pathname` 拼出多余盘符、`python3` 不存在等），不是这批改动引入。同一批在 Linux CI 全绿（RC 的 validate 通过）。是「只在 Windows 误报」，不是门岗有毛病，但会让本机拿不到完整绿灯；这类要改或登记，目前没改，需协调定。
- 卡顿巡检 `windows-freeze-sweep` 在同一棵树上冷启动第一次红了 3 步（点「生成素材」后假供应商 30 秒收到 0 单、其后一步因此连带红、3D 导演台帧间隔 1502ms），随后两次连跑全绿；v0.23.1 基线上 3D 导演台那一步同样 1.5 秒。判断是冷启动与机器忙的抖动，**不是**这批改动，但第一步的 0 单没有查出具体原因，列为未解的偶发。

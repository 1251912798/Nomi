聊天里的「指向元素」+ 付费确认卡（新版）

创作者那一刻

Agent 在聊天里说：「已在画布上起草了 3 个镜头」。创作者的眼睛在右边聊天，手在左边画布。

他要做的三件事，按顺序：
① 认：聊天里这三个东西，是画布上哪三个节点？不想读字、不想数。
② 决：花这笔钱行不行？只想知道几段、约多少。
③ 改：不对就改——改在节点里，改完回来点一下。

他会卡在哪：看不出聊天里的东西对应哪个节点；怕点错就花钱；想改，却发现卡里又有一套参数；跳去画布后找不回对话；窗口窄时一跳就把对话丢了。

已定的规则（10-22 用户拍板）

一个东西一个家：节点就是唯一的数据，聊天里不存第二份、不放小编辑器。
Agent 只指路：聊天里只放三样——指向元素、必要请示（花钱）、本来属于聊天的话。要改只有两条路：去节点里改，或者跟 Agent 说一句。

所以这批样张只回答两个问题：
A. 聊天里那个「指向元素」长什么样，才能一眼认出它是哪个节点？（P1 / P2 / P3）
B. 建在它上面的付费请示卡怎么排？（Q1 / Q2 / Q3）

命名：付费卡三种方案叫 Q1–Q3（请示），避免和功能名「D2」混，对应任务书的 D1–D3。按钮文案沿用现有付费卡：「生成」「全部生成（N）」「生成剩下 N 段」「取消」；卡头小字「生成 · Nomi 选的」。

这张画布怎么读
A1 一张脸：节点和指向元素的部件对照
A2 P1 / P2 / P3 × 6 种状态 + 组指向
A3 悬停两边同时亮 / 点击定位 + 闪一下
A4 窄窗口：点了先露出目标，再回到对话
A5 英文 / 暗色
Q1 一张卡一颗「确认」· 状态 · 想改的路径
Q2 一段一行，可单段先试 · 状态 · 想改的路径
Q3 对话里留指向，请示贴在输入框上 · 状态 · 路径
Q4 三种卡的英文 / 暗色 / 窄屏
Z 对比表 + 推荐

示例数据（纸船三镜头、型号、时长、价格）是样张用的占位，不是真实报价。价格行沿用现在付费卡的做法：算得出才印，算不出整行不印，不写免费 / 预算。

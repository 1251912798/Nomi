## 演练那一步为什么临时改了测试夹具

参考上传修复合进来以后，走查里的本地参考真走夹具的上传口。夹具上传口回的地址和它给图片任务的成片地址是同一个。产品取产物时会剔掉请求里发出去的地址（防供应商把输入原样回给我们），于是成片被当成回声剔掉，节点显示「已经生成，但结果没能取回」。

真供应商的成片地址不会等于我们上传的参考地址，所以这是夹具的缺陷，不是产品的问题。演练时把夹具临时改成上传口按次回独立地址，跑完按字节还原。夹具本身另开 PR 修，并给带上传参考的走查补上「成片落回原节点」的断言。

## 由此能说什么、不能说什么

- 能说：只给参考、不写参数名时，最终代码把参考投到模型声明的那个键，请求体里恰好一次，成片能落回原节点；整条确认卡之后的路是真的。
- 不能说：真模型会不会这样调工具（大脑是夹具）；成片画面好不好（成片图没留，这次也不判画面）。

## `report.json` 里那条 failure 是怎么回事

判定脚本 `tests/ux/_referenceLeakWire.mjs` 先从托管上传的响应文本里，用正则 `https?://[^\s"'\\]+` 抠出公网地址，再拿它去对请求体里的地址。这个正则遇到空格就停。带空格文件名的地址因此只抠到半截，和请求体里的完整地址对不上，就报了「对不回本地文件名」。

同一个脚本 10-24 跑 `first.png` / `last.png`（不带空格）时对号正常，见 `docs/evidence/2026-10-24-composer-b3-reference/paid/report.json`。

所以这是量具的缺陷，不是产品的问题，另开 PR 修：判定改成按可比地址对号，并补上带空格 / 中文 / `#` 文件名的单测。

## 由此能说什么、不能说什么

- **能说**：在修复后的构建里，服务商受理了两张带空格文件名的首帧 / 尾帧图，并按这两张图出了片。改前服务商会拒这种地址，这正是本单的起因。另外，首尾帧模式下「未用到」的参考没有上传。
- **不能直接说**：请求体里的写法就是 `%20`。原始网络账本按设计随临时目录删掉了，量具又没对上号，所以没有直接读到。这一条是推出来的，依据有三：
  - 构建里带修复标记；
  - 出站写法的单测（`electron/catalog/outboundReferenceUrl.test.ts`）；
  - 服务商受理了。
